Reproducibility

Every run is versioned, provenance-stamped, and auditable — so a result you get today can be traced, explained, and re-run later.

What you get

GuaranteeWhat it means
Versioned referencesEach reference is a pinned model version tied to a fixed CZI CELLxGENE Census snapshot. It does not change under you between runs.
Reproducible re-runsThe same input against the same reference and pipeline version reproduces the same analysis — every parameter that drives it is pinned and recorded.
Locked environmentEach run executes in a fixed, version-pinned software environment, isolated per run.
Self-contained reportResults travel with their own provenance: the HTML report is fully auditable on its own, offline.
Published benchmarksEach reference ships a benchmark card with the metrics it was selected on — results are disclosed openly.
Your data stays yoursProcessed in an isolated per-run job; never mixed into or used to train our models.

What every run records

Each reference build ships a provenance manifest beside the model, capturing exactly how it was produced. A result can always be traced back to the inputs and decisions behind it.

RecordedDetail
Census snapshotThe exact CZI CELLxGENE Census version the reference was built from.
CohortThe datasets and collections composing the reference, with DOIs and CC BY 4.0 attribution.
FilteringThe licensing and cohort filters applied at ingestion.
Gene spaceThe gene universe and highly-variable-gene selection the model was trained on.
Quality controlThe per-sample quality-control thresholds.
Label mapsOriginal study labels → Cell Ontology IDs → harmonized cell types.
Code versionThe exact pipeline commit that produced the build.
Maintainer note: the "What every run records" table mirrors the provenance captured by varnaops/reference_manifest.py (write_reference_provenance). Keep it in sync with the manifest schema whenever the build adds or drops a recorded field.
