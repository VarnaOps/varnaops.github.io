Overview

VarnaOps annotates a query single-cell dataset by mapping it onto a versioned reference atlas in a shared latent space, transferring cell-type labels by nearest neighbours, and surfacing marker genes, differential expression, and deviant populations in a single self-contained report. Each reference is built once from a public corpus and reused across queries; a query is mapped in without retraining the reference. Every stage records its parameters into a per-run provenance manifest, so a result can be traced back to the inputs and decisions that produced it.

Reference data & cohort selection

Reference atlases are built from the CZI CELLxGENE Census [11], a harmonized corpus of public single-cell data. A build is pinned to a fixed Census snapshot so the reference never changes underneath downstream results. A commercial-use license filter is applied at ingestion (on by default, fail-loud): only data whose license permits the intended use enters a reference.

References use a healthy backbone: cells are filtered to normal / control condition, so the atlas captures baseline cell-type structure. Disease is handled as a per-query layer at annotation time (Disease-state analysis), not baked into the reference. Genes are reconciled by a strict inner join across the constituent datasets, yielding a common gene space shared by every cell in the reference.

Quality control

Quality control is applied per sample. Cells are flagged on standard QC metrics — total counts, number of genes detected, and fraction of mitochondrial counts — using a median-absolute-deviation (MAD) criterion, which adapts thresholds to each sample's own distribution rather than imposing fixed cutoffs. Predicted doublets are removed with Scrublet [6]. At Census scale, QC runs as a single streaming pass over cells to bound memory.

\[ \mathrm{MAD} = \operatorname{median}_i \left| x_i - \operatorname{median}(x) \right| \] \[ \text{flag cell } i \ \text{ if } \ \left| x_i - \operatorname{median}(x) \right| > n_{\mathrm{MAD}} \cdot \mathrm{MAD} \]
\(x\) is a per-cell QC metric (counts, genes detected, % mitochondrial); \(n_{\mathrm{MAD}}\) is the sensitivity (default 5).

Gene & feature selection

The latent model is trained on a panel of highly variable genes (HVG), selected with the seurat_v3 variance-stabilizing method [5] in a batch-aware manner (batch = dataset of origin), so the panel is not dominated by any single study. The full reconciled gene space is retained alongside the panel: the embedding is learned on the HVG panel, while biological readouts (marker genes, differential expression) are computed on the full genes. Cells are therefore independent of the gene subset used for embedding — the panel shapes the latent space, not the downstream biology.

Label harmonization

Author cell-type labels differ across studies, so they are harmonized to a controlled vocabulary. Each original label is mapped to a Cell Ontology (CL) term [10] and then rolled up to a coarse, atlas-level set of cell types. The crosswalk (original label → CL identifier → harmonized cell type) ships with each build as a label registry. The same harmonization is applied to a held-out query before scoring, so benchmark numbers compare like with like.

Latent model: scVI / scANVI

The reference embedding is a single-cell variational inference (scVI) model [1]: a variational autoencoder over raw counts with a negative-binomial likelihood and the batch covariate supplied to encoder and decoder. Training streams minibatches directly from the sharded on-disk reference, so memory is independent of atlas size. The objective is the evidence lower bound, with the KL term ramped in over a warm-up schedule to avoid posterior collapse:

\[ \mathcal{L}(x) = \mathbb{E}_{q(z \mid x)}\!\left[\log p(x \mid z)\right] - \beta \, D_{\mathrm{KL}}\!\left(q(z \mid x) \,\|\, p(z)\right) \]
\(\beta\) ramps \(0 \to \beta^{*}\) over the warm-up epochs; \(\beta^{*}\) is tuned per atlas (recorded in the manifest) and reduced where the latent space is prone to collapse.

Labels are incorporated with scANVI [2], which extends the trained scVI model with a semi-supervised classification head over the harmonized cell types. The head is trained with a class-frequency-weighted cross-entropy so that rare cell types are not swamped by abundant ones:

\[ \mathcal{L}_{\mathrm{cls}} = -\sum_{c} w_c \, y_c \log \hat{y}_c, \qquad w_c \propto \frac{1}{n_c} \]
\(n_c\) is the number of reference cells of type \(c\); the weighting upweights rare types.

Reference mapping & label transfer

A query is mapped onto the reference with scArches [3], which fine-tunes the encoder online (covariates encoded) to project query cells into the existing reference latent space without retraining the reference. Labels are then transferred by weighted k-nearest-neighbours in that latent space. For large references, neighbours are found with an approximate inverted-file index (exact brute-force search below nref = 10,000), tuned for high recall:

\[ n_{\mathrm{list}} = \max\!\left(64,\ \left\lfloor \sqrt{n_{\mathrm{ref}}} \right\rfloor\right), \qquad n_{\mathrm{probe}} = \left\lfloor \frac{n_{\mathrm{list}}}{4} \right\rfloor \]

Each query cell receives a distance-weighted vote over its neighbours' labels, yielding a predicted type and a calibrated confidence. Cells that map far from any reference neighbourhood are flagged separately as candidate novel populations.

\[ p(c \mid x) = \frac{\sum_{i \in N_k(x)} w_i \, \mathbf{1}[\,y_i = c\,]}{\sum_{i \in N_k(x)} w_i}, \qquad w_i = \frac{1}{d(x, x_i)} \] \[ \hat{y}(x) = \operatorname*{arg\,max}_c \ p(c \mid x), \qquad \text{confidence} = \max_c \ p(c \mid x) \]
\(N_k(x)\) is the set of \(k\) nearest reference cells to query cell \(x\) in the latent space; \(d\) is Euclidean distance.

Novelty detection

Reference mapping places every query cell somewhere in the reference latent space, but a query may contain cell types or states the reference never saw. Because the encoder can only project into the existing manifold, such cells are not given a "no match" output — they receive a nearest-neighbour label like any other (reference mapping). Novelty detection is the safeguard: it scores how well each query cell is actually explained by the reference, independent of the label assigned.

The score reuses the latent kNN distances from reference mapping. For a query cell x it is the mean distance to its k nearest reference neighbours, compared against how far reference cells typically sit from one another. We precompute the reference's own self-distance distribution — each reference cell's mean distance to its k nearest reference neighbours — and set a threshold τ at a high quantile of that distribution. A cell is flagged when it is more isolated than reference cells normally are:

\[ s(x) = \frac{1}{k} \sum_{i \in N_k(x)} d(x, x_i) \qquad (\text{query} \to \text{reference}) \] \[ \tau = Q_{1-\alpha}\!\left(\left\{\, s_{\mathrm{ref}}(r) : r \in R \,\right\}\right), \qquad s_{\mathrm{ref}}(r) = \frac{1}{k} \sum_{j \in N_k(r)} d(r, r_j) \] \[ \operatorname{novelty}(x) = \mathbf{1}\!\left[\, s(x) > \tau \,\right] \]
\(R\) = reference cells; \(\alpha\) = tail mass (e.g. 0.01); \(d\) = Euclidean distance in the latent space.

The flagged fraction is a lower bound on the query's true out-of-reference content, for two reasons. First, the encoder maps a novel population into the convex hull of the existing manifold rather than onto a new island, so some genuinely novel cells land near reference cells and score below τ — they evade the flag. Second, τ is deliberately placed in the reference's own upper tail to suppress false positives. Detection is therefore conservative: a flagged cell is reliably outside reference coverage, but an unflagged cell is not certified as covered.

\[ T = \{\, \text{query cells whose true identity is absent from the reference} \,\} \] \[ D = \{\, x : \operatorname{novelty}(x) = 1 \,\} \] \[ \text{low false-positive threshold} \ \Longrightarrow\ D \subseteq T \ \ (\text{approx.}) \ \Longrightarrow\ \lvert D \rvert \le \lvert T \rvert \]
The reported novelty fraction reads as “at least this much is uncharacterized,” not a calibrated estimate.

The score does not separate biological novelty from strong technical shift — both place a cell outside the reference manifold — so a large novelty fraction on an unseen or zero-shot query is expected, and shrinks as the reference broadens. Flagged cells feed the cluster-analysis workflow: in the joint embedding they are clustered, where genuinely novel populations form coherent groups rather than scattering as isolated outliers.

Model selection & benchmarking

Models are checkpointed every epoch and selected on the metric actually deployed — kNN label-transfer accuracy on a harmonized, held-out, in-distribution query — rather than on a validation-loss proxy alone. The procedure is pre-committed: shortlist candidates by validation ELBO (scVI) and total validation loss (scANVI), score the survivors by macro-F1 on the held-out query, and promote the argmax (validation loss breaks ties). Macro-F1 is used because the product deploys nearest-neighbour transfer, not the classifier head, and because an unweighted per-class mean is balanced across abundant and rare cell types:

\[ \mathrm{F1}_{\mathrm{macro}} = \frac{1}{C} \sum_{c=1}^{C} \frac{2 \, P_c \, R_c}{P_c + R_c} \]
\(P_c, R_c\) = precision and recall for cell type \(c\); \(C\) = number of harmonized types.

Integration quality — how well batches mix while biological structure is preserved — is reported with scib-metrics [9] on a reference subsample. Each reference ships a benchmark card alongside its provenance manifest; the metrics are published openly, the trained weights are not.

Marker-gene validation

Predicted cell types are checked against canonical markers. Panels are curated through the Cell Ontology and sourced from CZ CellGuide: a marker set attached to an ontology term is inherited by its descendants via is_a relationships, so each harmonized type carries an appropriate panel. For every annotated type we score its panel across the query and report the standard scanpy / decoupler marker score together with an adjusted p-value, shown as produced rather than reduced to a bespoke statistic.

Differential expression

Per-cell-type differential expression is computed one-vs-rest. On GPU it is a regularized logistic-regression ranking (rapids-singlecell, rank_genes_groups_logreg) executed as chunked binary one-vs-rest with a per-group cell cap to bound VRAM; on CPU it is the Wilcoxon rank-sum test (scanpy.tl.rank_genes_groups, method="wilcoxon"). Either path emits the native ranked-gene tables — scores, log fold-changes, and adjusted p-values. These per-cell tests treat cells as replicates; donor-level inference is reserved for Disease-state analysis.

Cluster analysis

Query and reference are embedded together, a joint k-nearest-neighbour graph is built, and communities are detected with Leiden clustering on GPU (rapids-singlecell over cuGraph), visualized on a joint UMAP. Because query and reference share the latent space, populations the reference does not cover (Novelty detection) surface as coherent clusters instead of scattering. To keep the chosen granularity defensible, we report resolution diagnostics across a range of Leiden resolutions — silhouette width, and adjusted Rand / normalized mutual information between neighbouring resolutions — reusing the precomputed clusterings.

Pathway & transcription-factor activity

Functional activity is scored with decoupler over curated gene-set collections (e.g. GO Biological Process, MSigDB) and transcription-factor regulons. Activity is computed once on a bounded, representative subsample and then aggregated across groupings rather than re-scored per cluster or resolution, which keeps the GPU pass bounded at atlas scale. Outputs are per-type activity scores with the canonical enrichment heatmap.

Disease-state analysis

When donor metadata is present, disease-versus-control contrasts are tested at the donor level rather than per cell. Counts are aggregated into pseudobulk profiles per donor × cell type, then modelled with pyDESeq2 [8] (a negative-binomial generalized linear model with a Wald test) — the standard bulk RNA-seq approach, which avoids the pseudoreplication of treating individual cells as independent replicates.

\[ Y_{g,\,(d,t)} = \sum_{c \,\in\, \mathrm{cells}(d,t)} X_{g,c} \]
\(X_{g,c}\) = raw count of gene \(g\) in cell \(c\); cells are summed within each donor \(d\) × cell type \(t\) before testing.

Results are presented as volcano plots with protein–protein interaction context from STRING [12]. The path is guarded: it requires integer counts (rejecting normalized input), drops donors with fewer than 10 cells in a given cell type, and needs at least three donors per group for a contrast to run.

Report & interpretation

Every run renders a single self-contained HTML report (Jinja2) that bundles the figures, tables, and provenance into one file — portable, viewable offline, and shareable by link without the platform. The report is produced in audience-specific variants (customer, query-developer, reference) from one template.

Optionally, an LLM-generated interpretation accompanies the report: it summarizes the computed results in plain language, narrating the figures and statistics that were produced and citing the numbers behind them. The interpretation is descriptive only — it never alters or recomputes a result, so the underlying analysis remains the single source of truth.

Reproducibility & provenance

References are versioned and pinned to a Census snapshot; each runs in a locked, version-pinned software environment, isolated per run. Re-running the same input against the same reference and pipeline version reproduces the same analysis — every parameter that drives it is pinned and recorded. Results are reproducible at the level of methods and versions, not bit-identical floating point, since GPU kernels are not deterministic. Each reference build ships a provenance manifest beside the model; the per-run report carries the same record, making it a publication-ready methods trail. Version history is tracked in the changelog.
